Six phases run in sequence. LM sub-agents decide content, deterministic
Python owns geometry, and the only generative image-model call is the
enhancement in Phase 5.

1. **Plan** — read the source and prompt, decide the format, and write a
   validated panel spec (`figure.json`).
2. **Render each panel** — create one collision-checked diagram per panel.
   Panels are dispatched to parallel sub-agents (or one at a time with
   `--sequential`).
3. **Inspect + refine** — run a vision-model audit and automatic repair per
   panel.
4. **Compose** — lay out the panels in one composite `.drawio` and export the
   deterministic `full_figure.png`.
5. **Enhance** — restyle the figure into a camera-ready PNG while preserving
   labels, and fill any placeholder boxes. Embedded matplotlib plots are
   located in the composite and listed to the image model as
   reproduce-verbatim regions with their position and description; the
   model still regenerates the whole canvas, so this is a strong hint
   rather than a pixel guarantee. `ENHANCE_PROTECT_MPL=0` turns it off.
6. **Verify + repair** — audit the enhanced PNG, re-enhance if it fails, and
   ship the deterministic render as a fallback if no candidate is acceptable.

## Modes and correction loops

Phases 3 and 6 are audit-and-repair loops whose budgets are set by `--mode`:

| Mode | What it does | Runtime (with Opus 5.5) |
|------|--------------|-------------------------|
| `--mode light` | Fastest. Low reasoning effort; no per-panel inspection, no verify/repair. | ~10 min |
| `--mode medium` *(default)* | High reasoning effort; still no inspect or verify loops. Same pipeline as `light`, just thinking harder. | ~15 min |
| `--mode full` | Enables Phase 3 panel inspection/repair (3 inspects per panel) and Phase 6 verification/repair (3 verify attempts, 2 repairs). | ~30 min |

So the default run is **Plan → Render → Compose → Enhance**. `--panel-inspects`
and `--enhancement-attempts` override the loop budgets individually; see the
[CLI reference](cli.md#correction-loops-and-phase-control).

## What is (and is not) editable

Most `.drawio` components — boxes, arrows, formulas, labels — are fully
editable in [diagrams.net](https://app.diagrams.net) or the draw.io desktop
app. Two kinds of element are not directly editable:

- **Matplotlib subplots.** For visuals that are hard to draw in draw.io but
  easy in matplotlib (curves, histograms, heatmaps, …), the panel agent
  writes a small Python script, renders it to PNG, and embeds the image into
  the `.drawio` file. Phase 5 protects these regions (see above) but does
  not paste the original pixels back; `full_figure.png` keeps them exact.
- **Placeholder boxes.** Visuals that neither tool can produce well (photos,
  hand-sketched scenes, 3D renders) are left as gray dashed placeholder
  boxes in the deterministic figure. Phase 5 passes each placeholder's
  description to the image model, which fills the box in
  `full_figure_enhanced.png`; the box stays empty in `full_figure.drawio`
  and `full_figure.png`.

## Run directory layout

```
runs/<YYYY-MM-DD-HHMMSS>/
  figures/
    full_figure.drawio          editable draw.io source
    full_figure.png             deterministic export (no model involved)
    full_figure_enhanced.png    restyled variant (Phase 5, optional)
  figure.json                   the Phase 1 panel spec
  logs/                         every sub-agent and deterministic-step log
  events.jsonl                  the complete event stream of the run
  metrics/run_metrics.json      token counts and price estimates
```
